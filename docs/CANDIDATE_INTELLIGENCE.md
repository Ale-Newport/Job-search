# Candidate Intelligence

The structured model is additive to the existing CV vault and answer history. Migration `0007_candidate_intelligence` creates typed facts (backed by the existing historical fact IDs), entities, evidence relationships, scoped policies and answer provenance. Personal seed data and real-form evidence remain in `.local-data/`, outside Git.

`CandidateEngine.answer_question(question, form_context, job_context)` performs deterministic interpretation and derivation. Its asynchronous `answer` method also uses the configured local Ollama model to interpret unknown concepts or refine an unmappable enum within the same concept. The classifier sees the question and field constraints, not candidate facts. It returns a constrained concept/selector; code selects facts, computes dates/numbers and formats the answer. An existing grounded answer and a known missing fact cannot be replaced by a model classification. Classified answers remain marked for review. Classification errors and provider failures cannot create candidate facts.

The engine separates completed education from ongoing study, contractual notice from academic availability, present salary from expectations, and immigration-route descriptions from permission to work. Dated skill evidence is unioned rather than summed across overlapping projects; professional, academic and project exposure remain separate. Month-only historical dates retain their precision. A missing contract does not prove zero notice.

New typed identity data supersedes older CV values. Explicit Profile edits create authoritative versions; a draft/clear blocks reuse of the previous value. Equal-priority contradictory evidence produces an unknown answer. Lower-priority conflicting sources remain visible in Knowledge. The established Application profile reads typed person values directly; its generic facts table and patch endpoint cannot corrupt typed JSON. Scoped answers explicitly confirmed in the browser can fill a genuinely missing fact, but cannot revive cleared typed values or bypass an institution conflict. The review fingerprint includes all knowledge, policies and the London calendar date; changing any of those invalidates prior review. Derived values are evaluated anew rather than stored as primary relative facts.

Automatic narratives compose verified story clauses and, where relevant, quoted job context. Free-form model prose is not automatically inserted by this engine. This prevents new unsupported factual claims at the construction boundary; it does not certify the truth of a user-verified source. Role-dependent evidence ranking changes the selected project. Unsupported failure stories, legal assertions, current salary and personal attributes are not invented. Optional demographic policies choose an offered decline option or leave the field blank.

Profile → Knowledge exposes facts, evidence, linked entities, policies, conflicts, derivations and a question probe. Settings → Candidate Intelligence shows coverage over an explicit diagnostic question set. Percentages describe that denominator; they are not claims of universal ATS/question coverage. Existing document text can produce unverified CV and labelled immigration proposals. GitHub observations retain source URLs and blob hashes, without converting repository creation times into employment or experience dates.

## Calibration

`scripts/calibrate_intelligence.py` defaults to inspection only and requires a separate database. `--fill` is a separate, explicitly authorized operation that uses the normal browser filler in Review mode. Its browser class rejects every submission attempt. No bypass is provided for CAPTCHA, MFA or access restrictions.

The 3 October 2026 discovery run processed 1,532 postings across 11 configured public sources and selected the actual top ten recommendations. After destination-specific user authorization, these ten applications were exercised with the real candidate profile and approved CV, repeatedly correcting general failures and stopping before submission. The audit compares final observed control values against grounded answers; an attempted write is not counted as a verified answer.

Seven application forms were accessible: Trainline, Mytos, Shift Technology, two Blenheim Chalcot roles, Fifty One Degrees and Elwood. Haleon and British Council remain manual handoffs on Indeed (additional verification/sign-in also appeared during runs). BlackRock's Workday listing linked to an application page which did not expose a usable form. These three paths are not counted as completed forms.

Calibration fixes cover React Select's pointer-open behavior, hidden selected controls and country flags, dial-code decoration, Select2 tree options, geocoder disambiguation by verified city and country, clipped upload controls, dependent questions and asynchronous re-rendering. Dropdown and attachment proxies are validated against their observed DOM relationship. The runner verifies selected values and does not mark its own pre-write state as completed. Employer-populated values without supporting evidence are flagged for review. An application-entry URL can be opened by GET without clicking its possible submission handler; a page containing candidate inputs retains the submission boundary.

An in-progress qualification is explained truthfully when a free-text field presupposes graduation at the latest university. A recent-graduate inference uses a conservative completed-within-twelve-months interpretation, explicitly marked for review because the employer's recency definition is unknown. It does not assert programme eligibility. No ongoing master's is treated as a completed qualification.

The private audit, snapshots and screenshots are under `.local-data/intelligence-release/`. `docs/VERIFICATION.md` records the final counts and remaining restrictions. This is bounded evidence from ten selected destinations, not a guarantee of universal ATS coverage. Missing notice, employer-specific pay/office preferences, exact immigration evidence and separate legal consent remain unresolved without inventing answers.

## Immigration evidence

The user confirmed the Student route; an exact permission expiry, working conditions and future route were not supplied. These are distinct from general study dates. No legal eligibility is invented from Spanish nationality, a CAS or an expected completion date. Reference rules checked on 3 October 2026: [Appendix Student](https://www.gov.uk/guidance/immigration-rules/immigration-rules-appendix-student), [Graduate route](https://www.gov.uk/graduate-visa/overview). The application does not promise a future immigration outcome.
