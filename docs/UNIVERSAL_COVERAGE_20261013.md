## Actual option selection

The shared engine distinguishes free text from native selects, radio groups, checkbox groups and searchable custom menus. Search text is used to reveal options, then the engine selects an observed option and verifies its committed value. The location search uses the city while matching against verified country evidence, including a displayed metropolitan region such as Greater London. Editable search text alone is not accepted as a selection, even when it already spells the expected choice. Both intelligence and profile-only resolutions have scoped question identities; acceptance cannot transfer from another identically captioned field.

Local Laya receives only the exact question, a confirmed answer, supporting fact IDs and a bounded set of observed options whose meanings have already been checked. It cannot produce new answers or selectors. Sensitive choices remain local. Confirmed current work permission and the verified visa route can match a displayed disjunction such as “Student/Graduate Visa (with work rights)”; this does not establish Graduate status, unlimited hours or future eligibility. An uncertain or unavailable model uses an independently verified equivalent when one exists; unsupported subgroups, additional assertions and missing personal facts remain unanswered. Hidden option values do not establish the meaning of displayed labels.

Checkbox options can belong to one question even when each has a different internal name. Their shared question has one identity, while the individual DOM controls retain separate execution targets. This was repaired after an actual Checkout.com form exposed the issue. Both the pronoun group and the ethnicity group were independently verified as correctly selected on that form. Composite lived-experience questions remain unanswered when some constituent facts are missing.

Genuine Laya inference selected the supported Greater London option with confidence 0.9743. Four synthetic demographic/identity questions selected the expected candidate but returned confidence below the required threshold; those model decisions were rejected. The verified-equivalence fallback, rather than those low-confidence scores, establishes their safe mappings. Mocked API tests are separately identified as fixtures.
