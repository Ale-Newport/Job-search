# Universal application and discovery reliability — 12 October 2026

Historical report. The newer [13 October validation](UNIVERSAL_COVERAGE_20261013.md) records the current option-selection, Chrome-entry, source-storage and budget-test changes and their remaining limitations.

This is the current verification report. The signed update is installed in `/Applications/Meridian.app` using the existing stable Apple Development identity. It is not notarized. No test application was submitted. This report does **not** claim universal coverage or that every configured source is working.

## Installed changes

Factual answers use verified candidate evidence, educational levels, legal qualifiers, question context and required output precision. Generated prose uses the exact question, its help text, the approved professional CV and relevant employer context. It must pass evidence, relevance, repetition and application-level review. Missing incidents, qualifications, dates and consents remain unanswered.

Questions with the same label in different sections retain separate field identities through generation, writing, checkpoints and saved answers. Scoped secondary, undergraduate and postgraduate records do not substitute for one another. Date ranges use both evidenced dates; a vague `Result` label requests a grade rather than a graduation date. New verified education can supersede an older saved blank without deleting that history.

Form observation and validation cover grouped choices, custom selections, conditional and multi-page flows, file uploads and exact observed values. Successful writes require evidence of the resulting selected value, upload or text. Those mechanisms have automated browser coverage; the real employer evidence below is narrower.

Retries and manual edits now archive superseded answers instead of deleting them. Previous answers are visible in application details and are excluded from current approval and reuse. A final audit discovered thirteen original rows deleted by the former retry path. All thirteen were restored from the coherent pre-overhaul backup as history, without replacing current drafts.

Discovery reads supported public ATS APIs, published career data, hydration/CMS JSON, public job feeds, declared sitemaps and bounded anonymous rendering. Public searches are allowed; account and application mutations are blocked. The renderer reads actual DOM links after pending public job responses finish. Pagination, repeated pages, response limits, malformed records, redirects and SQLite ingestion contention have explicit handling. New employer boards observed in real listings are added and checked during the same daily cycle. Existing sources and enable/disable choices are retained. Manual checks have a per-source queue identity so a request for one employer cannot silently absorb a different source request.

MERIDIAN_TEST=1 PYTHONPATH=backend .venv/bin/pytest backend/tests -q

npm --prefix frontend run typecheck
