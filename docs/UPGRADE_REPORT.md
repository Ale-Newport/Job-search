# Reliability upgrade — implementation and evidence

The core upgrade is implemented in the existing Meridian app. Production data was preserved, a signed macOS bundle was built, and both source and packaged process isolation were exercised. The subsequent Citi entry-navigation fix was installed with recoverable app/database backups. Universal unattended completion is **not established**: the ten initial real forms still needed human input or unsupported-control handling, and some career pages remain unreadable by the public-source parser.

## Freeze audit and changes

Code inspection identified a shared browser/current-run bottleneck, browser evaluation/lifecycle waits outside normal Playwright action deadlines, blocking credential/configuration work on async paths, long SQLite lock waits, serial scheduler dependencies, repeated UI polling that could abort a slow response, stale DOM references, and ambiguous interrupted submissions. Regression tests reproduced browser disconnection, a fully stopped worker, delayed credentials, reloads, slow uploads and SQLite contention. These are demonstrated failure paths; historical production traces were unavailable, so the original intermittent freezes cannot all be attributed to one measured cause. No historical memory leak is claimed.

The supervisor persists tasks, leases, retries, heartbeats, semantic checkpoints and submission receipts in migration 0008. Browser processes/profiles are isolated per application, with two workflows by default and configurable concurrency up to six. Discovery, email, documents and manual browser sessions run independently. Missing heartbeats, no progress and excess memory trigger bounded recovery. A stopped worker cannot block the API. Account locks and submission receipts guard concurrent actions and uncertain replay. Review sessions can expire and resume without creating another task. Startup verifies exact private worker arguments before cleaning an orphan from a hard backend crash; unrelated browser processes are never broadly killed.

DOM actions revalidate fresh controls after reload/rerender. Multi-page state and document evidence are checkpointed. Navigation has a separate final-submit gate. Tall/nested iframe checks use the actual control's hit point, and per-field write budgets prevent repeated transformations from consuming the entire form budget. Uploads validate local files, formats, size and registered versions, then inspect selection/progress/errors/acknowledgement. CV and cover-letter generation supports PDF/DOCX/TXT; missing required documents are saved as grounded unapproved drafts for review.

## Discovery, recruitment and networking

All 72 required canonical employers are represented, including separate ByteDance/TikTok and Citadel/Citadel Securities records; seven existing additional employers remain. Aliases preserve original settings and distinct portals. Official entry pages and public boards derived from observed saved jobs are additive. Daily discovery queues at a configurable local time and catches up while the app is available; saved preferences remain unchanged. Public Workday pagination is bounded, and listing-only descriptions remain unknown. Complete authoritative ATS boards establish availability; failed/generic/truncated scans cannot close jobs by absence. Published deadlines retain evidence/timezone; unknown dates remain unknown and expired jobs leave active recommendations.

The final private-copy cycle visited 103 configured sources, found 3,899 job records (including duplicates) and added 1,003 jobs. Two sources represent email delivery rather than a web scan. There were 63 explicit scan failures: blocked HTTP requests or career pages without supported public structured postings. A failed entry-page scan may coexist with a working public board for the same employer. Configuration coverage is 79/79 companies; it is not 79 successful company scans. Details: [source-health report](upgrade-source-health.json).

Recruitment processing adds outcome/event dimensions, reference/alias/thread matching, ambiguity preservation, chronological progression guards, deadlines and reconciliation. Gmail history, Graph delta/immutable IDs and IMAP UID cursors commit after ingestion; duplicate messages do not duplicate events. The copied Gmail integration was connected with its last recorded sync on 4 October 2026. **Live OAuth/Keychain mailbox resynchronisation was not executed in this upgrade**; provider behaviour was tested with mocked responses and imported synthetic messages.

Networking stores manually verified public profiles, evidence-backed relevance, job links, accurate drafts, editable outreach, conversation imports and follow-ups. Job details provide Relevant people. The explicit handoff copies the approved message and opens the exact LinkedIn profile; outreach is recorded only after actual-send confirmation. No live message was sent. There is no authorised LinkedIn messaging integration configured. See [LinkedIn access requirements](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access); restricted messaging requires appropriate approved access, rather than ordinary profile permissions.

## Real-form preparation

The user approved verified-detail filling and approved-CV upload at ten exact destinations. The validation script pins those URLs and never invokes submission. The forms were Trainline/Ashby, Shift Technology/Greenhouse (two roles), Mytos/Lever, KLA/Workday, Endava/SmartRecruiters, Grayce/Workable, DigitalOcean/custom Greenhouse embed, Relay/Ashby and Farfetch/Lever. Several were senior or outside the preferred geography; they tested form diversity, not recommendation relevance or an intention to apply.

All ten finished within bounded limits; none was submitted and none reached verified final review. Four forms recorded CV selection/upload actions; one exposed independent filename acknowledgement. Native multipart selection before submission is not proof of server acceptance. Missing location/enum mapping, degree/visa evidence, legal consent, authentication/navigation and blocked controls required attention. Real dry runs uncovered false landing-page review, an overly broad iframe hit test and repeated phone-field rewriting; generic fixes and local regressions were added. Grayce's retry stopped after eight actions with a phone validation task instead of consuming 100 actions. Detailed outcomes and durations: [real-form report](upgrade-real-forms.json). Resolved-answer counts are not a measured correct-answer rate, and external crash recovery was not measured on these employers.

## Executed verification

- Full backend release run: **1,170 passed in 320.42 seconds**, with one Starlette test-transport deprecation warning. Three subsequent orphan-path/checkpoint-privacy regressions passed in a 53-test targeted run (7.19 seconds); the two concurrent recovery scenarios then passed again in 39.43 seconds.
- Expanded reliability/provider/document regressions: 26 passed, followed by 54 targeted tracking/recovery tests and 67 browser/reliability regressions.
- Three concurrent eight-step applications recovered from Chrome termination and SIGSTOP in separate timings. A sibling reloaded/inserted a conditional field and another delayed upload. Health requests stayed under one second, sibling attempts remained isolated, no application was duplicated and no submission receipt was created.
- UI smoke, complete candidate/application/email workflow, onboarding, recovery/reconnect and synthetic networking handoff passed. TypeScript typecheck, ESLint, Ruff, Rust formatting and six Rust tests passed.
- PyInstaller sidecar and signed Tauri macOS app builds succeeded. The final DMG checksum was verified. Notarisation was skipped because distribution credentials are not configured. The initial upgrade validation left the installation unchanged; the subsequent Citi entry fix was installed with backups.
- The final signed-bundle test used a QA path containing spaces, generated two documents in child processes, recovered a SIGSTOP browser worker, then recovered the same task after a hard backend crash with that worker stopped. Completed steps survived through attempt three and maximum measured API health latency was **0.0063 seconds**. No submission occurred. See [packaged-worker report](upgrade-packaged-workers.json).

The macOS app passed deep/strict signature verification with the existing local development identity. The DMG passed `hdiutil verify`; exact binary/image hashes are in [the release manifest](upgrade-release.json). This validates the signed sidecar and its workers, not a new end-to-end run of the native desktop window or a live mailbox sync.

At the end of the initial upgrade validation, the production snapshot contained 1,904 jobs, four applications, 263 facts, one document and 52 email messages, with its original 13 sources. Validation ran on copied or synthetic databases. The subsequent installation migrated the live schema and extended the watchlist without resetting storage; all existing IDs were checked for preservation.

## Citi entry-navigation follow-up

The engine now distinguishes a posting's Apply entry, Workday's Apply Manually method choice and the final Apply on a completed review page. It opens observed entry URLs, supports non-submit entry buttons outside forms, collapses duplicate entry links and recognises nested application routes while they hydrate. Section consent labels entry navigation separately. Explicit submit/form-associated controls remain gated, including an input-free final review with the same Apply label.

On Citi's Junior Software Engineer – Generative AI Platforms posting, the real engine followed Apply → Apply Manually and reached Create Account/Sign In, step one of seven, in 13.35 seconds. Empty facts and no documents ensured zero candidate data, uploads or submissions. The next required action is authentication. The full relevant browser/startup/recovery suite passed **96 tests in 129.50 seconds**, including seven new regressions; lint and TypeScript passed. The signed sidecar separately prepared both link and button entry fixtures through final review, one attempt each, without submission.

The updated signed app was installed at `/Applications/Meridian.app` and reopened. Before installation the live database held 2,092 jobs, five applications, 263 facts, one document and 52 messages; all IDs in those tables and the existing sources survived. The previous app and a coherent SQLite backup remain under `.build-cache/install-backups/20261009T195121Z-entry-fix/`. Installed binary hashes match the build, the DMG checksum passed and the native Today view was visually observed. Evidence: [Citi entry verification](citi-entry-verification.json); current artifact hashes: [release manifest](upgrade-release.json).

## Remaining limits

Some employer pages need a supported public feed, authenticated access or additional generic/custom-widget work. The report exposes these gaps rather than claiming universal completion. Workday boards are capped and do not provide full descriptions in list responses. Real forms still need unresolved candidate facts, legal consent and occasional manual control. Browser watchdogs and finite retry budgets provide bounded failure isolation, not a proof that every future macOS/web failure is impossible. Scheduling requires the app/backend to be running while the Mac is available; it is not an installed always-on launch daemon. Live Gmail/Graph/IMAP authorisation and LinkedIn partner messaging were not end-to-end tested.
